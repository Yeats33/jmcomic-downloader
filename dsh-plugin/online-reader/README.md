# Online chapter image service

`createOnlineReader({ client, fetch, codec, limits })` returns `{ readPage, dispose }`.
`client` must implement `getChapter(id, { signal })` and `getScrambleId(id, { signal })`. `fetch` defaults to global fetch; the default sharp codec preserves alpha (unlike the downloader's codec). All three are trusted host dependencies, not caller-controlled options. Hosts must keep and reuse one instance and call `dispose()` on shutdown.

`await readPage({ chapterId, page, signal })` accepts only a positive canonical i64 chapter ID, a 1-based integer page and an optional AbortSignal. It returns `{ chapterId: string, page: number, total: number, mime: string, data: string }`, with base64 image data. The requested basename comes exclusively from validated metadata; the service uses the fixed JM image CDN and refuses redirects. GIF is decoded and validated but returned byte-for-byte (`image/gif`), without requesting a scramble ID. The final GIF trailer byte is required to guard against a common truncation accepted by sharp; this is not an exhaustive structural validation of GIF. Static WebP, JPEG and PNG are restored and encoded as PNG (`image/png`); other or animated non-GIF formats are rejected. The basename extension must be gif/webp/jpg/jpeg/png, but the decoded image format determines behavior, even if it differs from the extension. An empty response is retried once with a server-generated cache-buster within the same deadline. No files are written. An instance caches metadata for at most two chapters for two minutes from successful insertion, using least-recently-used eviction. The cache stores only bounded copied filename strings and validated scramble IDs, never image bytes or URLs. New entries and scramble IDs are committed only when the page succeeds; failed or cancelled requests do not add them. If a cached image URL returns HTTP 404, that chapter's metadata is evicted; the failing request still reports the error, and the next retry fetches fresh metadata. GIFs do not request scramble IDs. Disposal clears the cache.

Default/hard limits: 16 MiB input, 16 MiB output (at most 22,369,624 base64 characters), 20 million total frame pixels, 100 GIF frames, 500 images in a chapter, 30 seconds including queue time. `limits` can lower `maxBytes`, `maxOutputBytes`, `maxPixels`, `maxPages`, `maxImages`, and `timeoutMs`, never increase them. One request runs at a time, with at most four queued. Queued cancellation is immediate. Native sharp work cannot be interrupted; cancellation/timeout/disposal is reported after it settles, with the slot held until then. `dispose()` aborts active and queued requests and permanently prevents new requests.

Service errors are `OnlineReaderError` with a stable `code`: `ABORTED`, `TIMEOUT`, `DISPOSED`, `BUSY` (queue full), `INVALID_METADATA`, `PAGE_OUT_OF_RANGE`, `NETWORK_ERROR`, `HTTP_ERROR` (includes `status`), `INVALID_RESPONSE`, `RESPONSE_TOO_LARGE`, `IMAGE_ERROR`, `OUTPUT_TOO_LARGE`. Invalid caller arguments throw `TypeError`. Upstream client errors are propagated unchanged; this preserves their API/HTTP error details. Native codec failures use `IMAGE_ERROR` with the original error as `cause`. This service assumes dependencies honor standard fetch redirect and AbortSignal semantics; injected clients/fetch/codecs are not a security boundary.

Run offline tests from the repository root: `node --test dsh-plugin/online-reader/*.test.mjs`.
